# gripperx_description

The robot model: URDF/Xacro, meshes and the RViz display configuration. No nodes.

For: anyone who changes the model or consumes it (the arm safety filter and the kinematics read
the joint limits and collision boxes from the URDF generated here). Status: 2026-11-17.

Short forms: URDF (robot description file), xacro (macro language that generates URDF), IMU
(inertial sensor, BNO085 on the robot), SR-17 (safety requirement 17 — arm safety envelope).

## Two entry files, and the difference matters

| File | Use |
|---|---|
| `urdf/gripperx_v1.urdf.xacro` | **Real robot.** `ros2_control` is included only under `enable_ros2_control`, with plugin `gripperx_hardware_interface/GripperXInterface`. |
| `urdf/gripperx_v1.gazebo.xacro` | **Twin.** Always includes `ros2_control` as `gz_ros2_control/GazeboSimSystem`, adds the Gazebo IMU (white noise only; bridged as `/imu/bno085/data` by `gripperx_gazebo`), and adds the odometry-publisher plugin that produces `/ground_truth/odom` with zero noise. |

Both pull the same macro libraries:

- `gripperx_v1.core.xacro` — the chassis: `base_footprint`, `base_link`,
  `chassis_link`, four steer links, four wheel links, `imu_link` (the BNO085 sensor frame the
  driver stamps; mount pose from `geometry.yaml`) and the geometry constants.
  **Geometry values are not restated here**: wheel radius, track, axle positions, steering
  limits, arm mount and joint limits, the LiDAR envelope and the chassis collision boxes are
  declared once in `gripperx_geometry/config/geometry.yaml`. Edit them there, never in the xacro.
- `gripperx_v1.arm.xacro` — the articulated SO101 arm (`arm_base_link`, `arm_limb1_link` to
  `arm_limb5_link`, `arm_gripper_link`, `arm_tcp_link`), exported from the CAD assembly, with
  `q = 0` the CAD assembly pose. Per-link collision boxes are generated by
  `scripts/arm_fit_collision.py`. The arm safety filter (SR-17) and the kinematics in
  `gripperx_arm` read the joint limits and collision geometry from the URDF.
- `gripperx_v1.lidar.xacro` — `lidar_link` and, in the twin, a ray sensor limited
  to ±160° so it reproduces the real LD06's ±20° blind rear wedge.
- `gripperx_v1.camera.xacro` — `camera_link` / `camera_optical_link`, optional
  Gazebo camera.
- `gripperx_v1.ros2_control.xacro` — the 4 position-commanded steer joints and 4
  velocity-commanded wheel joints, plus the `/hw/*` topic parameters.

## Launch

| Launch | What it does |
|---|---|
| `load_urdf.launch.py` | Runs `xacro` and starts `robot_state_publisher`. The workhorse everything else includes. Default `urdf_file` is the **gazebo** entry and default `use_sim_time` is **true**. |
| `rviz.launch.py` | Real-robot URDF + optional `joint_state_publisher_gui` + RViz on `rviz/display.rviz`. |
| `display.launch.py` | Backward-compatible alias for `rviz.launch.py`. |

```bash
ros2 launch gripperx_description display.launch.py
```

## Assets

`meshes/` holds the STL files (chassis, steer and wheel links, camera, the six arm link meshes
and the former rigid `arm_stowed.stl`, kept as an independent reference), referenced as
`package://gripperx_description/meshes`. `rviz/display.rviz` is the only RViz config.

`scripts/` holds standalone offline tools, **not installed** by `CMakeLists.txt` and not ROS
nodes: `decimate_meshes.py` (needs `fast_simplification`, not declared as a dependency),
`arm_from_cad_export.py` (reduces an `onshape-to-robot` export to the arm) and
`arm_fit_collision.py` (fits the arm collision boxes).

## Build and test

```bash
cd Software/ros2 && colcon build --packages-select gripperx_description
```

The package has no tests of its own; the arm tests in `gripperx_arm` build the URDF from it
(`xacro`).
